# 服务器部署说明：宝塔静态分发

域名：`https://wqty.online`。此步骤只分发软件，不迁移音乐库、QQ/网易云
登录或播放器后端。用户通过宝塔手动上传并修改站点配置，未代为登录服务器。
当前站点根目录为 `/www/wwwroot/wqty.online`；后续操作前仍应在宝塔核对。
官网公开源码与截图同时保存在仓库的 `deploy/site/`，不包含账号数据或安装包。

## 上传

1. 在宝塔「网站」中查看 `wqty.online` 的实际根目录，备份现有 `index.html`。
2. 上传 `electron/release/server-distribution/0.1.7/网站更新包-0.1.7.zip`，
   解压到该根目录并覆盖 `index.html`。不要删除已有的 `assets/`、`updates/`、
   证书或站点配置；本包只含首页文件。
3. 打开下面的地址确认首页版本与下载入口正确，更新文件地址仍返回真实文件，
   不能被重写成首页 HTML。

- 首页下载区：`https://wqty.online/#download`
- 更新清单：`https://wqty.online/updates/windows/latest.yml`
- 安装包：`https://wqty.online/updates/windows/Tiaolv-Setup-0.1.7.exe`
- 增量信息：`https://wqty.online/updates/windows/Tiaolv-Setup-0.1.7.exe.blockmap`

Nginx 默认支持字节范围请求。不要关闭 Range 或给更新目录套登录、验证码、
HTML 重写。`latest.yml` 不缓存；带版本号的安装包和 blockmap 可以长期缓存。
网页原有备案信息与 HTTPS 配置保持不变。

### 文件存在但下载返回 404

旧的宝塔配置可能只放行 `tiaolv-music-electron-setup-` 前缀，改名后的
`Tiaolv-Setup-` 会被白名单主动拦截，即使文件目录、权限都正确。
在现有 `/updates/windows/` 的 `location` 内，将文件名判断替换为：

```nginx
if ($uri !~ "^/updates/windows/(tiaolv-music-electron-setup-|Tiaolv-Setup-)[0-9]+[.][0-9]+[.][0-9]+[.]exe([.]blockmap)?$") {
    return 404;
}
```

新旧前缀同时保留，大小写与实际文件名一致。不要重复添加同路径的
`location`。通过宝塔配置检查并重载 Nginx 后，再核对下载地址。

## 客户端与后续发布

安装 0.1.2 后，检查优先访问本站；本站不可用时回退一次到 GitHub。
只有用户点击下载才获取安装包，通过主进程 SHA512 校验后才允许重启安装。
普通退出不安装，联网失败不影响本地播放。未接入在线更新的旧版先覆盖安装一次。

新版本的包、GitHub tag 和 `latest.yml` 必须具有相同版本号。先上传新的
EXE 与 blockmap，核对大小和哈希，再最后替换 `latest.yml` 和网页版本链接。
保留旧版 blockmap，避免破坏增量下载；增量不可用时库可回退完整安装包。
0.1.4 上传包附带 0.1.3 和 0.1.2 的 blockmap，供旧版本升级使用。保留服务器已有的
0.1.1、0.1.2 安装包和 blockmap，不清空 `updates/`。新版安装包统一使用
`Tiaolv-Setup-<版本号>.exe`，软件产品名、应用身份与本机数据目录不变。
上传包同时提供旧 blockmap 的 `Tiaolv-Setup-0.1.2.exe.blockmap` 别名，
供服务器按新名称查找旧版增量信息。GitHub 的旧 Release 保持原样，首次跨越
命名调整时可能回退到完整安装包下载；这不影响更新文件校验和安装。

GitHub 源码提交不等于软件发布。后续仍要发布对应 GitHub Release，
包含同一份安装包、blockmap 和清单，才有可用的备用更新源。
SHA512 不能替代发布者代码签名，不能防御清单和安装包同时被替换。
