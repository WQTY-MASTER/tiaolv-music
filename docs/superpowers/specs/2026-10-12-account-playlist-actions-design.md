# 在线账号歌单操作修复

## 范围

基于已发布的 0.1.4，生成 `0.1.5-beta.1` 本地安装包供用户验证。不提交或推送 Git，不发布 Release，不生成服务器上传包，不修改已有 0.1.4 文件。沿用现有界面和应用数据目录。

## 行为

1. 在线歌曲的“添加到歌单”打开所属平台当前登录账号的自建歌单选择器。打开时读取最新列表，保留加载、失败和重试状态；本地歌曲继续使用本地歌单。只向匹配平台且可编辑的普通自建歌单写入，不向他人歌单或系统喜欢歌单写入。
2. “我的喜欢”和自建歌单的批量工具栏增加“加入聚合歌单”。按当前可见的已选歌曲提交全部音源，按平台和歌曲 ID 去重，只写入本机聚合歌单，不修改平台收藏。取消选择目标不清空原选中歌曲。
3. 已收藏歌单右键提供“取消收藏”，保留自建普通歌单的删除确认和系统歌单保护。平台确认成功后更新列表；平台失败显示真实错误，不用仅本机隐藏冒充平台取消成功。
4. 两个平台登录、退出和换账号时失效旧界面及待处理列表请求，重新读取当前账号歌单。异步返回检查平台、账号及会话代次，旧请求不可更新新会话；歌单选择器不能沿用旧账号的目标。补齐账号歌单列表分页，去重且检测异常分页，避免固定首 100 条造成遗漏。

## 实现边界

复用已有账号 API、歌单权限字段、聚合歌单存储与批量操作组件；不更改登录协议或增加在线服务。针对歌单目标、账号上下文和聚合批量的共享逻辑采用小型帮助函数，避免重构整个 App。

已有“收藏歌单”的本机订阅覆盖数据不清空；这次取消收藏成功后覆盖状态跟随当前账号更新，失败不写本机成功状态。测试仅使用假数据，不替用户创建、删除歌单或修改真实收藏。

## 验证与交付

聚焦验证两个平台的新建歌单目标、批量去重与取消、收藏失败、账号 A/B 快速切换及分页；运行类型检查、构建和隔离的 UI 验证。更新后端运行包并核对安装包确实内置新代码。交付本地 EXE 及简短人工检查步骤，真实账号操作和安装升级由用户检查。
