# 播放切歌渐进渐出设计

## 目标

在“设置 → 播放”中增加“音乐渐进渐出”设置。用户主动切换上一首或下一首时，当前歌曲平滑淡出，新歌曲开始后平滑淡入。本地歌曲、QQ 音乐和网易云歌曲共用同一套逻辑。

## 设置界面

- 采用参考图的横向设置行：左侧标题和说明，右侧依次显示过渡时长控件与开关。
- 标题使用“音乐渐进渐出”，避免与真正的 Gapless Playback 混淆。
- 时长单位为毫秒，范围 `10–2000ms`，默认 `500ms`。
- 默认开启；关闭后保留用户设置的时长，但滑块和数值控件置灰不可操作。
- 设置写入 `localStorage`，并加入旧品牌存储键迁移清单。

## 播放行为

- 只有上一首、下一首入口触发过渡，包括主播放器、迷你播放器、任务栏、系统托盘和播放队列中的对应按钮。
- 暂停、恢复、拖动进度、直接点歌和打开歌单播放不触发。
- 播放自然结束后切到下一首时，旧曲已经没有剩余时长，因此只执行新曲淡入。
- 淡出时长不超过当前音频剩余时长；淡入时长不超过新歌曲可用时长。
- 过渡期间用户调整音量时，以最新用户音量作为目标；结束后音量必须恢复到该目标值。
- 连续快速切歌时取消前一次音量动画，以最后一次操作为准。

## 技术方案

- 保留现有单个 `HTMLAudioElement`，使用 `requestAnimationFrame` 更新 `audio.volume`。
- 抽出纯函数服务处理时长钳制和渐变进度，便于测试边界。
- 上一首/下一首通过统一的切歌过渡函数调用现有 `playTrack`，不改变各音源的地址加载流程。
- `playTrack` 接收仅供切歌路径使用的淡入选项；普通点歌继续使用原行为。

## 测试

- 单元测试覆盖时长范围、剩余时长上限、渐变进度边界。
- 契约测试覆盖设置位置、禁用状态、持久化键和上一首/下一首专用触发路径。
- 运行完整 Electron 测试与生产构建，并进行开发模式启动检查。
