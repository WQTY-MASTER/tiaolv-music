# 歌单收藏与单曲喜欢语义设计

## 目标

统一产品中的内容动作语义：单曲使用“喜欢”，歌单使用“收藏”。用户收藏其他人发布的网易云或 QQ 音乐歌单后，远端账号状态应同步，并在“音乐库 -> 我的歌单 -> 我的收藏”中展示。

## 数据流

- 网易云歌单收藏沿用 NeteaseCloudMusicApi 的 `/playlist/subscribe`。
- QQ 音乐不引入第二个服务；在现有 `qq-music-api` 中移植 `/songlist/collect` 能力，并复用当前登录 Cookie。
- Java 后端向前端暴露统一的歌单收藏写接口，将平台歌单 ID 去前缀后交给对应 Provider。
- 前端以账号歌单列表中 `createdByAccount === false` 的项目作为收藏状态来源。写入成功后重新加载账号歌单，避免仅做本地乐观状态而与手机端不一致。

## 界面行为

- 在线真实歌单详情在“播放全部”和“随机”旁显示收藏按钮。
- 未收藏显示“收藏”，已收藏显示“已收藏”；点击已收藏执行取消收藏。
- 用户自己创建的歌单、每日推荐、喜欢歌曲、最近播放和听歌排行等虚拟列表不显示收藏按钮。
- 写入期间按钮禁用；失败时保留原状态并显示明确错误。
- 音乐库歌曲卡文案改为“我的喜欢 / 我喜欢的歌曲”。所有单曲按钮和辅助文本使用“喜欢 / 取消喜欢”，不再称为收藏歌曲。

## 验证

- QQ API 单元测试验证 Cookie、歌单 ID 与 `op=1/2` 的映射。
- Java Provider、Service 与 Controller 测试验证两个平台的统一写入路径。
- 前端契约测试验证文案、收藏按钮可见性、状态刷新和音乐库分类。
- 运行 Electron 构建、Java 测试和 QQ API 测试。
