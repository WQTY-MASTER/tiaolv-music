# 最近播放批量管理与听歌排行筛选设计

## 目标

- QQ 音乐和网易云音乐的“最近播放”支持批量清除、批量喜欢、批量加入播放队列、批量加入自建歌单。
- 清除最近播放必须同步音乐平台云端；写入后重新读取云端列表，只把确认消失的歌曲视为成功。
- 批量喜欢和添加到歌单按当前音乐源调用对应云端接口。
- 听歌排行仅保留“最近一周”和“全部”，筛选器放在详情页头部右侧。
- 网易云听歌排行继续读取云端；QQ 听歌排行继续使用按账号持久化的本地统计。

## 接口设计

后端提供统一的账号接口：

- `DELETE /account/{provider}/recent-tracks`：请求体包含歌曲 ID，返回确认删除的 ID 和刷新后的最近播放。
- `POST /account/{provider}/playlists/{playlistId}/tracks`：请求体包含歌曲 ID，一次加入目标自建歌单。
- `GET /account/{provider}/listening-rank?period=week|all`：网易云将 period 映射到云端 `type=1|0`；QQ 将其映射到本地最近七天或全部。

QQ 最近播放删除调用 `music.musicasset.PlayRecentlyWrite.DeletePlayRecentlyInfo`，参数为一个 `vecIds` 数组与 `type: 2`。API 层先从云端最近播放把 song mid 映射成数字 song id，再批量删除并刷新验证。

网易云最近播放删除调用 `/api/play-record/batch/delete`，传入 `resourceIds`、`type: SONG`，以及当前列表末项的 `lastPlayTime` 和 `lastResourceId`；随后重新读取 `/record/recent/song` 验证。

## 前端交互

最近播放沿用详情列表的管理模式。进入管理后可多选歌曲，工具栏按音乐源提供清除记录、喜欢、加入播放列表和加入歌单。批量加入播放列表保持选择顺序、去重，并只持久化一次队列。

添加到歌单使用批量目标选择器，只显示当前音乐源中可编辑的自建歌单。“我喜欢”通过独立的喜欢操作处理，不作为普通目标歌单显示。

听歌排行的分段按钮位于详情页头部右侧，只显示“最近一周”和“全部”。

## 错误与限流

- 云端删除只发送一个批量写请求，不逐首循环。
- 遇到 403、429 或结果不明确时不自动重试写操作。
- 写入后的重新读取结果是最终依据；部分未删除时向用户报告成功数和失败数。
- 前端只有在后端确认后才更新列表与缓存。
