# 倾听音乐：本地模式与流媒体模式设计

**日期：** 2026-09-13  
**状态：** 设计方向已确认，等待文档复核后进入实施计划  
**适用范围：** Windows 桌面客户端第一阶段；Electron/Vue 前端、Java 后端、网易云音乐源

## 1. 背景

当前应用已经具备本地音乐扫描、播放、歌词、播放队列、收藏、最近播放、网易云搜索和部分推荐能力，但页面结构仍以网易云首页为中心。后续产品需要同时服务两种场景：管理本地音乐，以及使用在线音乐源搜索和播放。

本设计将“本地模式”定义为应用内的音乐库界面，而不是离线模式。用户切换到本地模式后仍然可以联网播放聚合歌单中的在线歌曲。

## 2. 目标

- 建立清晰的“本地模式 / 流媒体模式”界面边界。
- 登录网易云后显示当前账号的每日推荐、收藏和歌单。
- 同一时间只允许一个在线平台账号处于登录状态。
- 保留公共在线搜索和播放能力，不把所有公共接口误判为必须登录。
- 增加属于“倾听音乐”的本地聚合歌单，允许混合本地、网易云和未来 QQ 音乐歌曲。
- 为未来 QQ 音乐 Provider 保留稳定的扩展边界。
- 保留现有本地播放、歌词、队列和播放状态能力。

## 3. 非目标

- 第一阶段不实现 QQ 音乐 Provider，只预留接口和数据字段。
- 不绕过网易云或其他平台的会员、版权或地区限制。
- 不将受保护的在线音频永久下载或转换为本地文件。
- 不复制 Twilight Echo 的代码、界面素材或第三方仓库中的歌词文本。
- 不在前端直接请求网易云 API；所有在线请求继续经过 Java 后端。

## 4. 领域术语

### 4.1 本地模式

“倾听音乐”自己的音乐库视图。展示本地歌曲、文件夹、最近播放、聚合歌单等入口；网络仍然可用。

### 4.2 流媒体模式

当前在线音乐源的视图。第一阶段为网易云音乐，后续可切换为 QQ 音乐等其他 Provider。展示平台主页、发现歌单、音乐库、音乐云盘和最近播放等平台相关入口。

### 4.3 聚合歌单

属于“倾听音乐”本地数据库的歌单，不属于任何单一音乐平台。可以保存来自本地、网易云和 QQ 音乐的歌曲。聚合歌单只在本地模式的导航中显示，但其中的在线歌曲仍可联网播放。

### 4.4 当前在线账号

当前处于登录状态的一个平台账号。系统同时最多维护一个活跃平台账号：未登录、网易云账号或 QQ 音乐账号。

## 5. 用户界面

### 5.1 产品名称

软件名称、登录页品牌和页面标题统一使用“倾听音乐”。“网易云音乐”只作为音乐平台名称、账号来源或登录对象出现。

### 5.2 模式切换

- 左侧导航底部固定显示模式切换入口。
- 当前为本地模式时，入口显示“切换到流媒体模式”。
- 当前为流媒体模式时，入口显示“切换到本地模式”。
- 切换模式只改变导航和页面内容，不改变播放器、播放队列或当前歌曲。
- 模式切换状态在本地保存，下次启动恢复上次模式。

### 5.3 本地模式导航

参考用户提供的本地音乐界面，导航顺序为：

1. 主页
2. 所有歌曲
3. 艺术家
4. 专辑
5. 流派
6. 歌单
7. 聚合歌单
8. 文件夹
9. 最近播放

主页突出当前本地歌曲、曲库统计、最近播放和聚合歌单入口。现有的文件夹选择和扫描操作只在本地模式出现。

### 5.4 流媒体模式导航

参考用户提供的流媒体界面，导航顺序为：

1. 主页
2. 发现歌单
3. 音乐库
4. 音乐云盘
5. 最近播放

主页在未登录时显示登录引导和公开在线内容；登录网易云后，主视觉切换为“每日推荐”，并显示当前账号头像、昵称和推荐歌曲。

### 5.5 二维码登录页

- 登录页为独立页面，不使用小弹窗。
- 中央显示“倾听音乐”品牌和网易云二维码登录卡片。
- 二维码下方显示状态：加载二维码、等待扫码、待确认、登录成功、二维码过期、加载失败。
- 所有二维码请求由 Java 后端发起，并带时间戳。
- 前端每 3 秒查询一次 Java 登录会话状态。
- 离开登录页、登录成功或二维码过期后停止轮询。
- 二维码过期时支持点击刷新。
- 登录成功后显示账号昵称和头像，提供“进入主页”操作。

### 5.6 主页状态

未登录：

- 页面名称为“主页”。
- 主视觉突出本地音乐和最近播放。
- 可以展示不需要账号的公开推荐。
- 不伪造每日推荐数据。

网易云已登录：

- 页面名称仍为“主页”。
- 主视觉突出网易云“每日推荐”。
- 展示当前网易云账号昵称和头像。
- 显示每日推荐歌曲，并支持播放全部。
- 显示网易云收藏和用户歌单入口。

### 5.7 歌曲操作与聚合歌单

在歌曲行、搜索结果、歌单详情和播放队列中提供右键菜单或操作菜单：

- 加入聚合歌单
- 选择目标聚合歌单
- 创建新的聚合歌单

在歌单详情页提供“加入聚合歌单”操作，可将整张公开歌单或用户歌单加入本地聚合歌单。

## 6. 系统架构

```text
Electron / Vue
    ↓ HTTP
Java 后端
    ↓ 统一领域接口
MusicProvider 路由
    ├── LocalProvider
    ├── NetEaseProvider
    └── QqMusicProvider（后续）
    ↓
本地 NeteaseCloudMusicApi 或对应平台服务
```

### 6.1 Provider 边界

统一 Provider 至少提供以下能力：

```text
search
findTrack
resolveAudioUrl
loadLyrics
loadCover
loadPublicPlaylist
loadHomepage
loadDailyRecommendations
loadUserFavorites
loadUserPlaylists
saveFavorite
removeFavorite
addTrackToPlaylist
removeTrackFromPlaylist
```

公共能力和账号能力必须分开标记。Provider 可以在没有账号凭据时处理公开搜索、公开歌单和允许匿名访问的播放请求；账号相关接口必须显式使用当前平台会话。

### 6.2 播放流程

```text
用户点击歌曲
    ↓
根据 source 选择 Provider
    ↓
请求当前可用播放地址
    ↓
Java 返回本地代理或受控播放地址
    ↓
Electron 音频播放器播放
```

本地歌曲读取本地文件。在线歌曲不保存为永久音频文件；播放地址是否可用由平台权限和接口返回结果决定。请求失败时保留歌曲信息，并向用户说明需要登录、没有播放权限或资源暂不可用。

## 7. 登录与账号会话

### 7.1 API 草案

```text
GET  /auth/{provider}/qr/start
GET  /auth/{provider}/qr/status?sessionId={id}
GET  /auth/{provider}/account
POST /auth/{provider}/logout
GET  /auth/current
```

网易云 Provider 内部对应：

```text
/login/qr/key
/login/qr/create
/login/qr/check
/login/status
```

这些上游调用只由 Java 执行，二维码会话请求必须使用时间戳，避免被 NeteaseCloudMusicApi 缓存。

### 7.2 会话规则

- 登录成功后保持登录状态，直到用户主动退出。
- Java 保存并管理平台凭据，前端只接收登录状态和用户资料。
- 凭据使用操作系统安全存储抽象；Windows 第一阶段使用系统凭据保护，避免明文 Cookie 文件。
- 启动时检查已保存会话，不重复调用登录接口。
- 轮询会话有明确的开始、停止和超时边界。
- 切换平台前必须退出当前平台。
- 同一时间只允许一个平台账号处于 active 状态。

### 7.3 退出平台

退出网易云或 QQ 音乐时：

- 删除该平台登录凭据。
- 删除该平台账号信息、收藏缓存、用户歌单缓存和待同步操作。
- 不删除本地音乐、本地收藏、播放队列、最近播放。
- 不删除聚合歌单及其中任何歌曲信息。
- 聚合歌单中的该平台歌曲仍可尝试公开 API；若平台要求登录，则显示“登录对应平台后播放”。

## 8. 数据模型

### 8.1 统一歌曲

歌曲必须使用来源前缀或等价的结构化字段区分平台：

```text
track_id          倾听音乐内部唯一 ID
source             local / netease / qq
source_track_id    原平台歌曲 ID
title
artist
album
duration
file_path          仅本地歌曲使用
url                临时或代理播放地址
cover_url
lyrics
lyrics_source
```

不得仅使用裸数字 ID 作为跨平台歌曲主键。

### 8.2 平台账号

```text
provider_accounts
provider
provider_user_id
nickname
avatar_url
credential_reference
created_at
updated_at
```

数据库只保存凭据引用或加密存储标识，不保存明文 Cookie。

### 8.3 聚合歌单

```text
aggregate_playlists
id
name
description
cover_url
created_at
updated_at

aggregate_playlist_items
playlist_id
track_id
position
added_at
```

聚合歌单与平台账号无外键关系，因此退出平台不会删除它。

### 8.4 云端缓存与同步队列

平台收藏、用户歌单和同步操作必须带上：

```text
provider
provider_user_id
source_track_id 或 source_playlist_id
```

离线时的收藏和歌单修改先进入待同步队列，联网后按顺序提交。同步成功后删除队列项；失败时保留并显示重试状态。用户退出平台时删除该平台的云端缓存和待同步队列，但不影响聚合歌单。

## 9. 数据流

### 9.1 登录后主页

```text
二维码登录成功
→ Java 保存网易云会话
→ 获取账号资料
→ 前端切换为流媒体模式
→ 加载每日推荐、收藏和用户歌单
→ 主页显示每日推荐
```

### 9.2 加入聚合歌单

```text
用户右键在线歌曲
→ 选择“加入聚合歌单”
→ Java 保存歌曲完整元数据和 source 信息
→ 前端立即更新本地聚合歌单
→ 播放时再根据 source 请求对应 Provider
```

### 9.3 从平台歌单加入

```text
用户打开公开或用户歌单
→ 选择“加入聚合歌单”
→ 读取歌单歌曲元数据
→ 批量写入 aggregate_playlist_items
→ 保留原平台 ID
```

## 10. 错误处理

- 二维码过期：停止轮询，显示过期状态，支持重新生成。
- 登录成功但账号资料失败：保留会话，提示稍后刷新账号资料。
- 未登录访问每日推荐或私人歌单：返回结构化 `LOGIN_REQUIRED`，前端显示登录入口。
- 公共播放地址不可用：显示具体的“暂无播放权限”或“资源暂不可用”，不伪造地址。
- 当前平台服务离线：保留本地模式和本地播放，在线页面显示服务不可用。
- 平台切换请求进行中时：锁定重复操作，避免两个账号会话交叉。
- 网易云 API 缓存导致的登录状态异常：账号相关请求按接口规则增加时间戳或使用不缓存请求，避免频繁调用登录接口。

## 11. 安全与合规边界

- 不保存网易云或 QQ 音乐密码。
- 不在前端暴露平台 Cookie。
- 不使用公开共享的第三方代理服务保存用户账号凭据。
- 不绕过会员、版权、地区或 DRM 限制。
- 在线歌曲只做平台允许的流媒体播放。
- `Twilight Echo` 仅参考 Provider、模式和播放代理的架构思路；其 Apache-2.0 代码不直接复制。
- `amll-ttml-db` 的 CC0 许可不等于其中所有歌词原作都无版权；逐字歌词数据只在确认来源和使用范围后接入。

## 12. 实施顺序

1. 前端增加模式状态和两套导航，统一软件名称为“倾听音乐”。
2. 将现有主页拆分为本地模式主页和流媒体模式主页。
3. 增加 Java 网易云二维码登录会话接口。
4. 增加登录页、状态轮询、会话恢复和退出登录。
5. 接入账号资料、每日推荐、网易云收藏和用户歌单。
6. 增加聚合歌单数据库、右键加入和歌单批量加入。
7. 将聚合歌单接入现有播放队列和在线播放流程。
8. 增加离线同步队列和收藏/歌单双向同步。
9. 预留并测试 QQ Provider 接口，不在本阶段接入 QQ 上游服务。

## 13. 验收标准

- 用户能从左下角在本地模式和流媒体模式之间切换。
- 本地模式显示本地导航，流媒体模式显示平台导航。
- 本地模式仍能联网播放聚合歌单中的在线歌曲。
- 二维码登录成功后，重启应用仍保持登录，直到用户主动退出。
- 登录网易云后主页显示每日推荐，未登录时不伪造每日推荐。
- 退出网易云后，聚合歌单及其中歌曲信息完整保留。
- 聚合歌单可以保存本地和网易云歌曲，并按来源正确播放或提示权限状态。
- 前端不直接请求网易云 API，Java 统一负责平台调用。
- 现有本地扫描、歌词、队列、收藏、最近播放和播放状态功能不回归。
- 未来新增 QQ Provider 时无需重写模式切换、聚合歌单和播放器核心逻辑。
