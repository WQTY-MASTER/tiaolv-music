# 本地诊断包设计

## 目的

用户复现故障后，在设置的“关于”页面导出一个 ZIP，配合截图和简短的
复现步骤反馈。现有“复制诊断信息”保留，不能把环境版本信息当成错误日志。

## 方案

选择本地滚动日志加手动导出。只提供日志目录需要用户自行找文件、脱敏；
自动上传需要额外服务器、授权和隐私治理，本次不接入。

- 主进程保存启动失败、未捕获异常、窗口渲染崩溃和本地服务退出信息。
- 捕获打包客户端的后端、QQ 和网易云服务错误输出，包含错误栈、退出码
  和发生时间，不保存完整请求、响应、进程环境或一般播放内容。
- 前端保存 Vue 错误、未处理的 Promise 错误和统一 API 请求失败；请求仅
  记录模块、方法、脱敏后的路径、状态码和耗时，不记录查询参数或请求体。
- 更新记录当前来源、检查/下载/安装阶段和实际失败原因，界面保留现有流程。
- 六类日志按大小滚动，每类最多三个 1 MiB 文件；限制单条长度和待写队列，
  日志写入失败不得影响播放或更新。
- 诊断概要包含版本、系统、组件版本、服务状态、窗口尺寸、显示缩放，
  以及允许列表中的主题模式和主题色。它不能证明显示器实际亮度或 HDR 效果。
- 不自动截图。显示问题由用户另附截图；不读取自定义背景图片或图片路径。

## 安全与导出

写入和导出均脱敏 Cookie、Authorization、token、密码及个人目录等信息。
ZIP 只收集诊断模块自己的固定文件名，不扫描音乐库、数据库、账号配置、
缓存或任意目录。日志和导出数量、大小受限，不跟随符号链接。

主进程使用成熟 ZIP 库生成压缩包。仅可信主窗口主框架可以通过保存对话框
导出；用户取消时不创建文件，失败时显示错误，可再次导出。小窗口只能通过
受限、限频的接口上报错误，不能选择路径、导出或读取日志。

## 验证与范围

聚焦验证脱敏、滚动限额、拆分输出、导出内容、取消/失败重试和 IPC 授权，
运行类型检查、生产构建和“关于”页按钮的电脑/窄窗口检查。
不进行账号写入，不改播放功能，不自动发布新版本。本次不直接修改引导页
配色；已发现的深色选中按钮低对比度问题单独确认修改范围。
