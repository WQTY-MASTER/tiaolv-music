# 统一页面数据缓存

## 目标

流媒体模式中的页面在本次应用运行期间复用已经成功加载的数据。用户切换页面或前进、后退时应立即看到上次内容，不因重复请求清空列表、显示骨架屏或产生明显闪烁。缓存不跨应用重启。

## 方案

新增独立的内存缓存服务，统一管理页面数据快照、加载中的请求和更新时间。业务页面不直接维护各自的缓存 Map，而是通过相同接口读取、写入、失效和强制刷新。现有 Vue 响应式状态仍负责渲染；缓存保存可恢复的普通数据快照，不保存组件实例或 DOM。

缓存采用 stale-while-revalidate：命中缓存后立即恢复内容并维持成功状态；数据未超过 5 分钟时不发请求，超过 5 分钟后在后台刷新，刷新期间继续显示旧数据。后台刷新失败时保留旧数据并显示非阻塞提示。用户点击刷新按钮时跳过有效期并等待新请求，但仍不主动清空旧内容。

同一缓存键的并发加载共享一个 Promise，防止快速切换产生重复请求。缓存最多保留 100 个页面快照，超出后按最近最少使用顺序淘汰。失败、登录失效和中止的请求不覆盖已有成功快照，也不形成新的数据缓存。

## 缓存键

缓存键由以下稳定字段组成：

- 当前账号：音乐源、用户 ID；公共页面使用 `public`。
- 页面类型：首页、发现、音乐库、每日推荐、歌单详情、歌手详情、关注、粉丝、用户主页、最近播放、听歌排行、云盘、私人雷达、私人漫游、搜索。
- 页面参数：歌单或歌手 ID、搜索词、搜索类型、排序、分页、漫游模式等会改变返回内容的参数。

键只保存业务标识，不包含昵称、封面等可变展示字段。退出登录时清除该账号命名空间；切换账号或音乐源时保留旧账号缓存但不读取它，便于本次运行内切回账号时恢复数据。

## 覆盖范围

统一缓存覆盖所有会因导航重新请求的网络页面数据：

- 流媒体首页、发现歌单、每日推荐及推荐栏目。
- 账号音乐库摘要、我喜欢、创建和收藏的歌单详情。
- 最近播放、听歌排行、云盘。
- 歌手详情及歌曲、专辑分页。
- 关注、粉丝及用户主页分页。
- 私人雷达、私人漫游当前批次。
- 搜索结果，按音乐源、关键词、类型和页码区分。

本地音乐库、播放队列、设置和纯静态页面已经由长期响应式状态或持久化数据管理，不重复建立页面快照；它们仍遵循现有刷新行为。

## 导航与显示

进入页面时先查询缓存。命中后同步恢复页面所需的列表、分页信息、选中实体和成功状态，再决定是否后台刷新。未命中时沿用当前首次加载状态。离开页面不会清空可复用数据；迟到的请求只有在账号、音乐源和页面上下文仍匹配时才能更新当前界面，但可以写入其原始缓存键。

返回、前进和侧边栏切换使用同一条缓存读取路径。页面搜索框、排序或分页变化产生新键，回到旧参数时可恢复对应快照。

## 写操作与失效

写操作成功后优先就地更新相关快照，使当前页面和返回后的页面立即一致：

- 喜欢或取消喜欢：更新歌曲状态、我喜欢列表及其数量和封面。
- 创建、删除或收藏歌单：更新音乐库歌单摘要并失效受影响详情。
- 从歌单移出歌曲、批量操作或同步排序：更新该歌单详情、数量和首曲封面。
- 关注或取消关注：更新歌手状态并失效关注列表和相关用户主页摘要。
- 云盘变更：更新云盘列表。

无法安全局部合并时，只失效最小相关键；下次进入仍可先显示旧快照并后台刷新。账号退出时立即删除该账号全部缓存，防止另一账号看到旧数据。登录凭据和 cookie 永不进入缓存。

## 刷新与错误处理

每个已有刷新按钮调用统一的强制刷新入口。强制刷新成功后替换快照；失败时保留旧内容并给出错误提示。接口返回登录失效时清除账号缓存并进入现有重新登录流程。后台刷新不把页面切换为全屏错误态。

## 测试

缓存服务单元测试覆盖有效命中、过期后台刷新、并发请求合并、失败保留旧值、LRU 淘汰、账号清除和强制刷新。前端契约或浏览器测试覆盖页面返回不清空、搜索和分页键隔离、账号隔离、写操作同步缓存，以及后台刷新失败仍保留内容。现有播放、收藏、歌单排序和账号切换测试继续运行。

## 非目标

本轮不把页面响应写入 localStorage、IndexedDB 或后端数据库，不缓存音频文件、歌词文件和封面二进制，也不改变后端 HTTP 缓存策略。现有音频与资源缓存继续由各自模块负责。
